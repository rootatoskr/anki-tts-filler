# anki-tts-filler

Робота з нотами в уже створеній колоді/notetype в Anki через [AnkiConnect](https://github.com/amikey/anki-connect). Два режими:

- **cards** – заповнення нових нот: текст із `cards.txt` + аудіо через `edge-tts`, додається напряму в Anki.
- **audio** – збирання mp3 для фонового слухання з уже наявних нот: норвезька, пауза, український переклад, пауза, норвезька ще раз.

Скрипт не визначає вигляд картки чи структуру колоди – тільки дані. Схема полів (яка колода/notetype, які поля норвезькі/переклад/аудіо) задається у файлах (`presets/*.toml`), спільна для обох режимів – не привʼязана до конкретної мови чи колоди.

## Швидкий старт

Пресети для наявних 4 типів нот (`ordforrad`, `verb`, `substantiv`, `cloze`) уже лежать у `presets/` і закомічені в репозиторій – створювати їх заново не треба, новий пресет потрібен лише для нового типу ноти.

Передумови: Anki відкритий з увімкненим аддоном AnkiConnect, `ffmpeg`/`ffprobe` в PATH, `uv sync --no-editable`.

**Додати нові картки в Anki** (режим `cards`):

1. Вписати картки в `cards.txt` у форматі `поле: значення`, блоки через порожній рядок (поля беруться з нотетайпу в Anki):
   ```
   substantiv: en bror
   substantiv_uk: брат
   bestemt_ental: broren
   ubestemt_flertall: brødre
   bestemt_flertall: brødrene
   ```
2. Запустити з назвою пресету:
   ```bash
   uv run anki-tts-filler cards substantiv
   ```
   Аудіо для норвезьких полів генерується й заливається в Anki автоматично, ноти додаються в `deck_name` пресету. Без аргументу – список доступних пресетів.

**Зібрати mp3 для прослуховування** (режим `audio`):

```bash
uv run anki-tts-filler audio 'tag:no\_familie'
uv run anki-tts-filler audio 'deck:language-no::no-verb'
```

Один аргумент – Anki-запит (як у рядку Навігатора, підкреслення в тегах екрануються зворотним слешем). Тип ноти кожної знайденої ноти визначається автоматично, тож один запит може охопити відразу кілька типів (наприклад `deck:language-no` дає і іменники, і дієслова в одному файлі). Результат – `out/<назва>.mp3`: норвезька → пауза → переклад → пауза → норвезька (скільки разів – `content.repeat_no` у `settings.toml`, типово `1`). При першому запуску `settings.toml` створюється автоматично за зразком `settings.example.toml`, там же – голоси, швидкість, довжина пауз.

## Як це працює

### Режим cards

1. Колоду й поля створити та редагувати вручну в Anki (поля, шаблон картки, CSS).
2. Для кожного типу карток створити свій пресет – файл `presets/<назва>.toml`.
3. Записати список карток у `cards.txt` у форматі `ключ: значення`.
4. Запустити `anki-tts-filler cards <preset>` – аудіо генерується через `edge-tts` + `ffmpeg` і заливається в Anki, картки додаються через AnkiConnect.

### Режим audio

1. Норвезька сторона береться з готових `[sound:...]` у полях ноти, якщо файл є в `collection.media`. TTS вмикається лише як фолбек.
2. Українська сторона озвучується `edge-tts` і кешується на диску.
3. `ffmpeg` склеює доріжки з паузами в один файл.
4. Запустити `anki-tts-filler audio '<query>'` – `query` це Anki-запит (той самий синтаксис, що й у рядку Навігатора: `tag:...`, `deck:...`, з довільними фільтрами на кшталт `-is:suspended`). Тип ноти кожної знайденої ноти визначається автоматично за `modelName` – один запуск може охопити кілька типів нот одночасно (наприклад `deck:language-no` збирає і іменники, і дієслова).

В обох випадках Anki має бути відкритий з увімкненим аддоном AnkiConnect.

## Встановлення

```bash
uv sync --no-editable
```

- Утиліти:
    - `ffmpeg` і `ffprobe`
    - [AnkiConnect](https://ankiweb.net/shared/info/2055492159) в **Anki** (`2055492159`, `Tools → Add-ons → Browse & Install`)

## Використання

```bash
uv run anki-tts-filler cards verb
uv run anki-tts-filler audio 'tag:no\_familie'
```

Вхідні картки для `cards` беруться з `cards.txt` у поточній директорії, схема для обох режимів – з `presets/<preset>.toml`.

Без аргумента до `cards` скрипт друкує список доступних пресетів:

```bash
uv run anki-tts-filler cards
```

Підкреслення в тегах у `query` треба екранувати зворотним слешем (`tag:no\_familie`), так само як у рядку пошуку Навігатора – це шаблон Anki на один символ.

## Пресети (presets/\*.toml)

Каталог `presets/` лежить поруч із `cards.txt`, у поточній директорії. Один файл – один тип ноти; назва файлу без `.toml` є назвою пресету для режиму `cards`. Режим `audio` сканує всі файли одразу і зіставляє за `model_name`, а не за назвою файлу. Якщо каталог порожній або його нема – скрипт створить `presets/example.toml` при першому запуску `cards` і вийде. Готовий приклад – `preset.toml.example` та `cards.txt.example`.

```toml
deck_name = "MyDeck::MySubdeck"
model_name = "MyNoteType"
translation_field = "field_translation"

[audio_fields]
audio_field_one = "field_one"
```

- `deck_name` / `model_name` – мають дослівно збігатися з назвами вже створених в Anki (для підтек – з `::`, як у самому Anki). `deck_name` потрібен лише режиму `cards`.
- `translation_field` – поле перекладу; потрібне лише режиму `audio` для української сторони. Режим `cards` його ігнорує.
- `[audio_fields]` – `назва_аудіо_поля = "з_якого_текстового_поля_генерувати_аудіо"`. Ці аудіополя мають існувати в полях Anki. Для `cards` – це поля, які генеруються TTS при створенні (якщо секції нема – аудіо не генерується взагалі). Для `audio` – це й є норвезька сторона: список текстових полів (кілька – для форм на кшталт `infinitiv`/`presens`/...) з готовим `[sound:...]` у відповідному аудіополі.

Список і порядок текстових полів для `cards` пресет не задає – вони беруться напряму з нотетайпу в Anki (`modelFieldNames`), мінус поля з `[audio_fields]`. Додати новий тип ноти – покласти ще один `.toml` у `presets/`, нічого не редагуючи в наявних файлах.

## Формат вхідного файлу (cards.txt)

Кожна картка – блок пар `ключ: значення`, розділений порожнім рядком:

```
field_one: значення першого поля
field_two: значення другого поля
```

Поле можна не писати взагалі або лишити значення порожнім – в обох випадках у Anki воно піде порожнім, без помилки. А от ключ, якого нема серед полів нотетайпу (одруківка в назві поля) – помилка, картка не додається; перевіряється в скрипті, не через Anki.

На кожну картку створюється одна нотатка напряму в Anki. Перед додаванням увесь список перевіряється через `canAddNotesWithErrorDetail`: дублікати й нотатки, які Anki відхилив би, рахуються окремо, скрипт не падає. Повтори всередині самого `cards.txt` теж ловляться – за першим полем нотетайпу, як це робить і сам Anki.

## Аудіо в режимі cards

Аудіо кешується в `audio_cache/` за хешем `текст + голос + темп`, тому зміна `TTS_VOICE`/`TTS_RATE` у `config.py` дає нові файли, а не перевикористання старих. У медіатеку Anki заливаються тільки ті файли, яких там ще нема.

## Налаштування режиму audio (settings.toml)

Якщо `settings.toml` немає, `anki-tts-filler audio` створить шаблон і вийде – готовий приклад із коментарями є в `settings.example.toml`.

| Ключ | Що робить |
| --- | --- |
| `anki_url` | адреса AnkiConnect |
| `cache_dir` | кеш озвучених TTS-фрагментів (`.cache/tts`) |
| `work_dir` | тимчасові файли складання (`.cache/work`) |
| `concurrency` | скільки TTS-запитів паралельно |
| `voice.no`, `voice.uk` | голоси edge-tts |
| `voice.rate_no`, `voice.rate_uk` | швидкість окремо для кожної мови, напр. `-40%` |
| `gap.after_no` | пауза після норвезької: час згадати переклад |
| `gap.after_uk` | пауза після української |
| `gap.within_side` | пауза між формами однієї сторони (infinitiv, presens, ...) |
| `gap.between_cards` | пауза між картками |
| `content.repeat_no` | скільки разів норвезька повторюється після перекладу: `no -> uk -> no` (repeat_no разів), типово `1` |
| `content.use_anki_media` | брати готові mp3 з Anki замість TTS |
| `content.include_note` | озвучувати приклади з поля `note` |
| `output.dir` | каталог для mp3 (типово `out/`) |
| `output.bitrate` | бітрейт вихідних mp3 |

Кеш TTS для режиму `audio` (`.cache/tts`) окремий від `audio_cache/` режиму `cards` – різна схема кешу (по мові, а не глобальний голос) і файли не заливаються в Anki, лишаються локально.

## Структура проєкту

```
src/anki_tts_filler/
    main.py – точка входу (entry point anki-tts-filler), розбір режиму cards/audio
    config.py – константи, завантаження пресетів (Preset) і налаштувань audio (Settings)
    ankiconnect.py – HTTP-клієнт AnkiConnect (localhost:8765) з обробкою помилок
    parser.py – парсинг cards.txt, побудова словника полів (режим cards)
    audio.py – TTS + обрізання тиші для полів, що заливаються в Anki (режим cards)
    note_cards.py – побудова карток з нот Anki за схемою пресетів (режим audio)
    audio_build.py – склейка ffmpeg, паузи, оркестрація одного запиту в один mp3 (режим audio)
    tts_cache.py – TTS з кешем по (текст, голос, темп, гучність) (режим audio)
presets/ – по файлу на тип ноти (схема полів/колоди/notetype), спільна для cards і audio
preset.toml.example – приклад пресету
settings.example.toml – приклад налаштувань режиму audio
cards.txt – вхідний файл із картками (режим cards)
cards.txt.example – приклад cards.txt
audio_cache/ – локальний кеш згенерованих mp3 (режим cards)
out/ – готові mp3 для прослуховування (режим audio)
.cache/ – кеш TTS-фрагментів і тимчасові файли ffmpeg (режим audio)
```
