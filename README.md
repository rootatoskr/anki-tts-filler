# anki-tts-filler

Робота з нотами в уже створеній колоді/notetype в Anki через [AnkiConnect](https://github.com/amikey/anki-connect). Три режими:

- **cards** – заповнення нових нот: текст із `cards.txt` + аудіо через `edge-tts`, додається напряму в Anki.
- **audio** – збирання mp3 для фонового слухання з уже наявних нот: цільова мова, пауза, переклад, пауза, цільова мова ще раз.
- **pdf** – та сама вибірка нот, але на друк: кожне поле картки окремим рядком, картки одна за одною.
- **resync** – переозвучення вже створених нот за їхнім поточним текстом: коли картку відредагували вручну, а аудіо лишилось старим. Ціль – назва пресету або Anki-запит.
- **draft** – сирий список «дві мови в одному рядку» з `draft.txt` перетворюється на `cards.txt` за межею скриптів кирилиця/латиниця, без ШІ (тільки пресет `base`).

Скрипт не визначає вигляд картки чи структуру колоди – тільки дані. Схема полів (яка колода/notetype, які поля цільової мови/перекладу/аудіо) задається у файлах (`presets/*.toml`), спільна для всіх режимів.

Конкретних мов у коді немає. Сторони картки називаються **target** (мова, яку вчать) і **native** (мова, якою знають); які це мови, вирішують голоси в `settings.toml`, а те, що залежить від самої мови – артиклі, які не враховуються при сортуванні, та літери після `z` – задається в секції `[language]`. Приклади в цьому README норвезько-українські, бо таким є проєкт, з якого інструмент виріс.

## Швидкий старт

Пресети для наявних 4 типів нот (`base`, `verb`, `substantiv`, `cloze`) уже лежать у `presets/` і закомічені в репозиторій – створювати їх заново не треба, новий пресет потрібен лише для нового типу ноти.

Передумови: Anki відкритий з увімкненим аддоном AnkiConnect, `ffmpeg`/`ffprobe` в PATH, `uv sync --no-editable`. Обидва режими читають `settings.toml`; якщо його нема – перший запуск створює шаблон і виходить.

**Додати нові картки в Anki** (режим `cards`):

1. Вписати картки в `cards.txt` у форматі `поле: значення`, блоки через порожній рядок (поля беруться з нотетайпу в Anki):
   ```
   substantiv: en bror
   substantiv_uk: брат
   bestemt_ental: broren
   ubestemt_flertall: brødre
   bestemt_flertall: brødrene
   ```
2. Запустити з назвою пресету:
   ```bash
   uv run anki cards substantiv
   ```
   Аудіо для полів цільової мови генерується й заливається в Anki автоматично, ноти додаються в `deck_name` пресету. Без аргументу – список доступних пресетів.

   Теги ноти – рядком `tags: kapittel_4 familie` усередині картки (через пробіл) і/або прапорцем `--tag`, який дістається всім карткам запуску:
   ```bash
   uv run anki cards substantiv --tag kapittel_4
   ```
   Саме за цими тегами потім працюють `audio`, `pdf` і `resync` (`tag:kapittel\_4`).

**Зібрати сторінку на друк** (режим `pdf`):

```bash
uv run anki pdf 'tag:no\_familie'
```

Той самий запит і ті самі пресети, що й в `audio`. Результат – `out/<назва>.pdf`.

**Зібрати mp3 для прослуховування** (режим `audio`):

```bash
uv run anki audio 'tag:no\_familie'
uv run anki audio 'deck:language-no::no-verb'
```

Один аргумент – Anki-запит (як у рядку Навігатора, підкреслення в тегах екрануються зворотним слешем). Тип ноти кожної знайденої ноти визначається автоматично, тож один запит може охопити відразу кілька типів (наприклад `deck:language-no` дає і іменники, і дієслова в одному файлі). Результат – `out/<назва>.mp3`: цільова мова → пауза → переклад → пауза → цільова мова (скільки разів – `content.repeat_target` у `settings.toml`, типово `1`). При першому запуску `settings.toml` створюється автоматично за зразком `settings.toml.example`, там же – голоси, швидкість, довжина пауз.

**Переозвучити картки за поточним текстом** (режим `resync`):

```bash
uv run anki resync base
```

Аргументом назва пресету – береться нотетайп із його `model_name`, тобто всі ноти цього типу в колекції, незалежно від колоди:

```
пресет base (type-language-no-basic) -> нот: 262
```

Без аргументу друкується перелік пресетів, як у режимі `cards`. Пресет без секції `[cards]` – помилка, переозвучувати нема чого.

Anki-запит працює теж – той самий, що й в `audio`/`pdf`; ним і націлюються на одну картку:

```bash
uv run anki resync 'nid:1234567890'
uv run anki resync 'deck:language-no::no-verb'
```

Аргумент, що збігається з назвою пресету, означає пресет; будь-який інший іде в Anki як запит. Що саме вибралося, видно в першому рядку виводу.

Для кожної знайденої ноти аудіополя з `[cards]` пресету переозвучуються за поточним текстом відповідних текстових полів і заливаються в Anki. Ноти типів без секції `[cards]` пропускаються, а поля, чий готовий `[sound:...]` вже відповідає поточному тексту, не перезаписуються.

Спершу складається план – які поля справді зміняться, – і озвучуються тексти саме з плану: порівняння імені файлу синтезу не потребує, тож зайвого TTS немає. Якщо під запит підпало `resync.confirm_from` нот або більше (типово `5`), режим показує план і чекає підтвердження:

```
deck:language-no::no-verb -> нот: 20
зміниться нот: 20 (аудіополів: 80)
  nid:1788199556372 å bo (4 поле)
  ... ще 15 нот
переозвучити? [y/N]
```

Без термінала (запуск зі скрипта) це вважається відмовою, щоб широкий запит не переозвучив колекцію мовчки.

## Як це працює

### Режим cards

1. Колоду й поля створити та редагувати вручну в Anki (поля, шаблон картки, CSS).
2. Для кожного типу карток створити свій пресет – файл `presets/<назва>.toml`.
3. Записати список карток у `cards.txt` у форматі `ключ: значення`.
4. Запустити `anki cards <preset>` – аудіо генерується через `edge-tts` + `ffmpeg` і заливається в Anki, картки додаються через AnkiConnect одним запитом `addNotes`. Колода з `deck_name` має вже існувати в Anki, інакше скрипт зупиниться (Anki створив би її мовчки).

### Режим audio

1. Сторона цільової мови – поля з `[audio] target`, переклад – з `[audio] native`. Озвучення береться з готових `[sound:...]` у полях ноти, якщо файл є в `collection.media`; TTS вмикається лише як фолбек.
2. Сторона перекладу озвучується `edge-tts` і кешується на диску.
3. `ffmpeg` склеює доріжки з паузами в один файл.
4. Запустити `anki audio '<query>'` – `query` це Anki-запит (той самий синтаксис, що й у рядку Навігатора: `tag:...`, `deck:...`, з довільними фільтрами на кшталт `-is:suspended`). Тип ноти кожної знайденої ноти визначається автоматично за `modelName` – один запуск може охопити кілька типів нот одночасно (наприклад `deck:language-no` збирає і іменники, і дієслова).

### Режим pdf

1. Вибірка нот і порядок карток ті самі, що й у режимі `audio`: порядок задає ключ `order` кожного пресету. Поля свої – із секції `[pdf]`, тож поле з прикладами потрапляє в друк тоді й тільки тоді, коли воно є в `[pdf] fields`.
2. Рядки картки – це поля зі списку `[pdf] fields` пресету, у тому ж порядку. Порожнє поле рядка не дає, підписів полів нема.
3. Сторінка верстається як HTML і переганяється в PDF через headless Chrome – нових залежностей проєкт не тягне. Якщо Chrome не знайдено, лишається HTML: його можна надрукувати в PDF з браузера.
4. Верстка: A4, дві колонки, картки розділені порожнім рядком, над карткою її номер дрібним сірим. Усі поля картки одного розміру й кольору, картка не розривається між колонками. HTML, з якого друкується PDF, після друку видаляється – в `out/` лишається тільки `out/<назва>.pdf`.

PDF – самостійна шпаргалка: список карток вибірки, щоб проглянути очима. З mp3 того самого запиту він не синхронізується і не має цього робити – режими незалежні.

В усіх режимах Anki має бути відкритий з увімкненим аддоном AnkiConnect.

## Встановлення

```bash
uv sync
```

Ставить пакет у `.venv` у editable-режимі, тож правки в `src/` діють без перевстановлення. Для незмінної копії – `uv sync --no-editable`, але тоді після кожної правки потрібен повторний `uv sync`.

Команда встановлюється під двома іменами: коротким `anki` і повним `anki-tts-filler`; у прикладах нижче вживається коротке.

Python – від 3.11 (межу задає `tomllib` зі stdlib). Локально проєкт розробляється на 3.14 (`.python-version`), CI проганяє тести на обох.

- Утиліти:
    - `ffmpeg` і `ffprobe`
    - [AnkiConnect](https://ankiweb.net/shared/info/2055492159) в **Anki** (`2055492159`, `Tools → Add-ons → Browse & Install`)

## Використання

```bash
uv run anki cards verb
uv run anki audio 'tag:no\_familie'
```

Вхідні картки для `cards` беруться з `cards.txt` у поточній директорії, схема всіх режимів – з `presets/<preset>.toml`. Усі файли (`cards.txt`, `draft.txt`, `presets/`, `settings.toml`, `audio_cache/`, `out/`) шукаються в директорії запуску; якщо чогось немає, скрипт створює шаблон і друкує повний шлях – так видно, що запуск стався не з того каталогу.

Без аргумента до `cards` скрипт друкує список доступних пресетів:

```bash
uv run anki cards
```

Підкреслення в тегах у `query` треба екранувати зворотним слешем (`tag:no\_familie`), так само як у рядку пошуку Навігатора – це шаблон Anki на один символ.

## Чернетка карток (режим draft)

```bash
uv run anki draft
```

Читає сирий список із `draft.txt` і пише результат у `cards.txt`. Якщо `draft.txt` немає – створює порожній і виходить, як це робиться з `cards.txt` і `settings.toml`. Наявний `cards.txt` перезаписується.

Ніякого ШІ – чиста регулярка: рядок ділиться по межі скриптів кирилиця/латиниця, тому працює миттєво, безкоштовно і без мережі.

Режим працює **тільки з пресетом `base`** (нотетайп `type-language-no-basic`, поля `production`, `recognition`, `note`): назви полів у коді конкретні, для іншого пресету вони були б просто неправдою.

Рядок списку – одна картка: спершу частина латиницею (можливо кілька речень), одразу за нею – переклад кирилицею, за потреби – дужки. Саме тому режим і лишається вузьким: він працює тільки для пари «латиниця + кирилиця» і тільки з пресетом `base`. Ніякого форматування змісту немає – recognition і production лишаються точно тими шматками рядка, якими були, буква в букву. Єдині дві механічні правки:

- **Тире стає en dash (`–`), з одним пробілом з обох боків** – навіть якщо в рядку пробілу не було взагалі (`disse -ці` → `disse – ці`). Але тільки те тире, біля якого хоч з одного боку є пробіл: дефіс усередині слова (`e-post`, `T-bane`, `смс-повідомлення`) – частина самого слова і лишається недоторканим. Тире, що просто розділяло норвезьку й українську частини, після цього прибирається зовсім – воно не переклад, а розділювач.
- **Дужки йдуть у `note`, тільки якщо в рядку рівно одна пара.** Дві й більше пари дужок – ознака, що це не окрема ремарка, а частина самого перекладу, і рядок лишається одним цілим без `note`.

```
til kjøkkenet на кухню
en kunde - один клієнт
en kokk (et yrke) кухар (професія)
etter disse verbeneпісля цих дієслів (disse -ці)
```

Приклад вище дає:

```
recognition: til kjøkkenet
production: на кухню

recognition: en kunde
production: один клієнт

recognition: en kokk (et yrke)
production: кухар (професія)

recognition: etter disse verbene
production: після цих дієслів
note: disse – ці
```

Зверни увагу на третій рядок: обидві пари дужок (`(et yrke)` і `(професія)`) лишились буквально в тексті, бо їх дві – жодна не стала окремим `note`. У четвертому ж рядку дужки одні, тому їхній вміст пішов у `note`, а тире (без жодного пробілу в джерелі) отримало пробіл з обох боків.

Переклад може бути й цифрами замість кирилиці (`førti 40`, `to tusen og ti 2010`) – тоді в `production` іде суцільний хвіст із цифр у кінці рядка. Цифри посеред норвезької частини під це не підпадають.

Рядок, у якому не знайшлося ні кирилиці, ні числа в кінці, картки не дає – зауваження про нього зупиняє запис, `cards.txt` не чіпається:

```
увага: рядок 1: немає кириличної (української) частини - 'no cyrillic at all'
```

| Прапорець | Що робить |
| --- | --- |
| без прапорців | `draft.txt` → `cards.txt` |
| `--append` | дописує в кінець `cards.txt` |
| `--print` | друкує результат у stdout, нічого не пише |
| `--stdin` | читає список із потоку замість `draft.txt` |

В Anki нічого не потрапляє автоматично: `draft` лише готує файл, далі ти переглядаєш його очима і запускаєш `cards`.

## Пресети (presets/\*.toml)

Каталог `presets/` лежить поруч із `cards.txt`, у поточній директорії. Один файл – один тип ноти; назва файлу без `.toml` є назвою пресету для режиму `cards`. Режим `audio` сканує всі файли одразу і зіставляє за `model_name`, а не за назвою файлу. Якщо каталог порожній або його нема – скрипт створить `presets/example.toml` при першому запуску `cards` і вийде. Готові приклади – закомічені `presets/*.toml` та `cards.txt.example`.

Кожен режим бере поля зі своєї секції – нічого не домислюється:

```toml
deck_name = "language-no::no-verb"
model_name = "type-language-no-verb"

[cards]
audio_infinitiv = "infinitiv"
audio_presens = "presens"

[audio]
order = "linear"
target = ["infinitiv", "presens", "preteritum", "presens_perfektum"]
native = ["infinitiv_uk"]
examples = "note"

[pdf]
order = "sorted"
fields = ["infinitiv", "presens", "preteritum", "presens_perfektum", "infinitiv_uk", "note"]
```

- `deck_name` / `model_name` – мають дослівно збігатися з назвами вже створених в Anki (для підтек – з `::`, як у самому Anki). `deck_name` потрібен лише режиму `cards`. `model_name` має бути різний у різних пресетах: режими `audio`, `pdf` і `resync` зіставляють пресет із нотою саме за ним, тож два пресети на один нотетайп – помилка, а не два варіанти на вибір.
- `[cards]` – `назва_аудіо_поля = "з_якого_текстового_поля_генерувати_аудіо"`. Без секції аудіо при створенні нот не генерується взагалі.
- `[audio]` – `target` це сторона мови, яку вчать, `native` – переклад; порядок у списку = черга озвучення. Готові `[sound:...]` беруться за мапінгом із `[cards]`: для поля `infinitiv` шукається `audio_infinitiv`. Якщо `[cards]` нема, все озвучується через TTS.
- `[audio] examples` – необовʼязкове поле з прикладами у форматі `цільова мова – переклад` (розділювач – en dash). Кожна пара стає окремою карткою `приклад → переклад → приклад`; рядки без en dash пропускаються. Без ключа приклади не озвучуються.
- `[pdf]` – `fields` це рядки картки у цьому ж порядку. Порожнє поле рядка не дає.
- `order` у кожній із секцій `[audio]` і `[pdf]` – порядок карток цього типу ноти в цьому режимі: `"linear"` (типово, як у Anki), `"random"` або `"sorted"` (за абеткою першого рядка). Режими потребують різного: для фонового слухання корисний `random`, щоб не вивчалася послідовність, а шпаргалка має бути стабільною, тому в пресетах проєкту стоїть `sorted`.

Абетка рахується без початкового артикля чи частки і з літерами цільової мови в кінці – обидва списки задаються в `[language]` у `settings.toml`. Для норвезької з прикладів це означає, що `en bok` стоїть на `b`, `å lese` на `l`, а `æ`, `ø`, `å` – після `z`.

У запит часто потрапляють ноти кількох типів одразу. Тоді порядки не заважають один одному: картки випадкових пресетів перемішуються між своїми ж позиціями, впорядковані сортуються між своїми, а лінійні лишаються там, де стояли.

Секції немає – режим цей тип ноти не обслуговує: без `[audio]` ноти не потраплять у mp3, без `[pdf]` – у друк, без `[cards]` не буде аудіо при створенні.

Назви полів звіряються з нотетайпом у Anki при кожному запуску (`modelFieldNames`): одруківка дає помилку з переліком відсутніх полів, а не тихо порожній рядок. Ключі самого пресету теж звіряються: невідомий ключ верхнього рівня або в секції (`modle_name`, `[audio] wat`) – помилка, а не мовчазне замовчування.

Список і порядок текстових полів для `cards.txt` пресет не задає – вони беруться напряму з нотетайпу в Anki, мінус аудіополя з `[cards]`. Додати новий тип ноти – покласти ще один `.toml` у `presets/`, нічого не редагуючи в наявних файлах.

## Формат вхідного файлу (cards.txt)

Кожна картка – блок пар `ключ: значення`, розділений порожнім рядком:

```
field_one: значення першого поля
field_two: значення другого поля
```

Поле можна не писати взагалі або лишити значення порожнім – в обох випадках у Anki воно піде порожнім, без помилки. А от ключ, якого нема серед полів нотетайпу (одруківка в назві поля) – помилка, картка не додається; перевіряється в скрипті, не через Anki.

Окремий ключ `tags` – це теги ноти, а не поле: значення ділиться пробілами, як у самому Anki.

```
field_one: значення першого поля
tags: kapittel_4 familie
```

Теги з `--tag` дістаються всім карткам запуску й обʼєднуються з тегами рядка. Якщо в нотетайпі справді є поле з назвою `tags`, пріоритет має поле – тоді теги задаються тільки прапорцем.

На кожну картку створюється одна нотатка напряму в Anki. Перед додаванням увесь список перевіряється через `canAddNotesWithErrorDetail`: дублікати й нотатки, які Anki відхилив би, рахуються окремо, скрипт не падає. Повтори всередині самого `cards.txt` теж ловляться – за першим полем нотетайпу, як це робить і сам Anki.

## Аудіо в режимі cards

Ім'я файлу – це відпечаток самого тексту: `md5(текст|голос|темп)`, перші 16 символів, з префіксом `langdeck_`. Гучність входить у ключ, тільки якщо вона не `+0%` – інакше всі вже залиті в Anki файли отримали б нові імена й продублювалися в медіатеці. Звідси й випливає, як `resync` розуміє, що аудіо застаріло: він рахує відпечаток поточного тексту й порівнює з іменем у полі, нічого не синтезуючи.

Текст перед хешуванням чиститься тією самою функцією, що й у режимі `audio` (`clean_text`): знімаються теґи й `[sound:...]`, розгортаються `{{c1::...}}` і HTML-сутності, `&nbsp;` і подвійні пробіли зводяться до звичайного. Одне чищення на весь проєкт – інакше той самий текст дав би різні файли в різних режимах.

Аудіо кешується в `audio_cache/`, тому зміна `voice.target`/`voice.rate_target` у `settings.toml` дає нові файли, а не перевикористання старих. Синтез, повтори й атомарний запис спільні з режимом `audio` (`tts_cache.py`): обірваний запуск не лишає напівзаписаного mp3. У медіатеку Anki заливаються тільки ті файли, яких там ще нема.

## Налаштування (settings.toml)

Якщо `settings.toml` немає, будь-який із режимів створить шаблон і вийде – готовий приклад із коментарями є в `settings.toml.example`.

Ключі, що раніше називалися мовами, перейменовані на сторони. Старе ім'я не ігнорується: скрипт зупиняється і пише, на що саме його замінити.

| Було | Стало |
| --- | --- |
| `voice.no`, `voice.uk` | `voice.target`, `voice.native` |
| `voice.rate_no`, `voice.rate_uk` | `voice.rate_target`, `voice.rate_native` |
| `voice.volume_no`, `voice.volume_uk` | `voice.volume_target`, `voice.volume_native` |
| `gap.after_no`, `gap.after_uk` | `gap.after_target`, `gap.after_native` |
| `content.repeat_no` | `content.repeat_target` |
| `[audio] no`, `[audio] uk` у пресеті | `[audio] target`, `[audio] native` |

Нового ключа два: `gap.between_repeats` (раніше між повторами стояла `gap.after_no`, тобто довга пауза «на подумати») і секція `[language]`.

Файл спільний для всіх режимів: `cards` і `resync` беруть із нього `anki_url`, `concurrency` і голос цільової мови (`voice.target`, `voice.rate_target`, `voice.volume_target`), секції `gap`, `content` і `output` – тільки для `audio`, а `language` – для сортування за абеткою (`audio`, `pdf`) і атрибута `lang` сторінки на друк.

Межа між цим файлом і пресетом така: пресет каже, **що** береться з ноти і в якому порядку (поля кожного режиму, `order`, поле з прикладами), а `settings.toml` – **як** це звучить і виглядає (голоси, паузи, повтори, бітрейт, кеші, адреса AnkiConnect). Нове налаштування, що стосується вибору вмісту, має йти в пресет, а не сюди.

| Ключ | Що робить |
| --- | --- |
| `anki_url` | адреса AnkiConnect |
| `cache_dir` | кеш озвучених TTS-фрагментів (`.cache/tts`) |
| `work_dir` | тимчасові файли складання (`.cache/work`) |
| `concurrency` | скільки TTS-запитів паралельно |
| `voice.target`, `voice.native` | голоси edge-tts: мови, яку вчать, і мови, якою знають |
| `voice.rate_target`, `voice.rate_native` | швидкість окремо для кожної сторони, напр. `-40%` |
| `voice.volume_target`, `voice.volume_native` | гучність окремо для кожної сторони, напр. `+0%` |
| `language.code` | код мови для атрибута `lang` сторінки на друк |
| `language.sort_prefixes` | артиклі й частки, які не враховуються при сортуванні за абеткою |
| `language.sort_extra_letters` | літери, які в абетці цільової мови йдуть після `z`, у порядку самої абетки (див. обмеження нижче) |
| `gap.after_target` | пауза після цільової мови: час згадати переклад (`0` – без паузи) |
| `gap.after_native` | пауза після перекладу |
| `gap.within_side` | пауза між формами однієї сторони (infinitiv, presens, ...) |
| `gap.between_repeats` | пауза між повторами цільової мови (коли `content.repeat_target` > 1) |
| `gap.between_cards` | пауза між картками |
| `content.repeat_target` | скільки разів цільова мова повторюється після перекладу: `target -> native -> target` (repeat_target разів), типово `1` |
| `content.use_anki_media` | брати готові mp3 з Anki замість TTS |
| `resync.confirm_from` | від скількох нот `resync` питає підтвердження (типово `5`) |
| `output.dir` | каталог для mp3 (типово `out/`) |
| `output.bitrate` | бітрейт вихідних mp3 |

`language.sort_extra_letters` розраховане на абетки **на латиниці**, які дописують літери в кінець (норвезька `æøå`, шведська `åäö`): кожна така літера отримує ключ «після `z`». Для абетки не на латиниці це не працює – її літери й так мають вищі коди, тож перелічені опинилися б перед рештою. Літеру, місце якої всередині абетки (українська `ґ` після `г`), цим ключем теж не поставити.

Кеш TTS для режиму `audio` (`.cache/tts`) окремий від `audio_cache/` режиму `cards` – різні схеми імен (у `cards` імена мають лишатися стабільними, бо на них посилаються `[sound:...]` у вже створених нотах) і файли `audio` не заливаються в Anki, лишаються локально.

## Тести й лінтер

```bash
uv run python -m unittest discover -s tests
uv run ruff check src tests
```

Тести на `unittest` зі stdlib – окремих залежностей не потрібно. Покривають чисті функції: розбір пресетів і `settings.toml`, чищення HTML нот, абетку, порядок карток, паузи між сторонами, розбір `cards.txt` і чернетки, вибір цілі та план для `resync`. Те, що вимагає Anki, ffmpeg чи мережі, тестами не покрите – це перевіряється запуском самих режимів.

`ruff` ставиться разом із dev-групою (`uv sync --group dev`). Набір правил – `E`, `W`, `F` з `preview = true`: саме preview вмикає `E221` і `E241`, тобто заборону вирівнювання по стовпцях. Форматер `ruff` не вживається – він переписав би наявний стиль цілком.

CI (`.github/workflows/tests.yml`) на кожен push проганяє лінтер і тести на 3.11 і 3.14.

## Структура проєкту

```
src/anki_tts_filler/
    main.py – точка входу (команди anki / anki-tts-filler), розбір режимів
    config.py – константи, завантаження пресетів (Preset) і налаштувань audio (Settings)
    ankiconnect.py – HTTP-клієнт AnkiConnect (localhost:8765) з обробкою помилок
    parser.py – парсинг cards.txt, побудова словника полів (режим cards)
    audio.py – схема імен медіафайлів Anki + обрізання тиші (режим cards)
    note_cards.py – побудова карток з нот Anki за схемою пресетів (режим audio)
    audio_build.py – склейка ffmpeg, паузи, оркестрація одного запиту в один mp3 (режим audio)
    pdf_build.py – верстка HTML і друк у PDF через headless Chrome (режим pdf)
    resync.py – переозвучення вже створених нот за поточним текстом полів (режим resync)
    draft.py – розбір рядка по межі кирилиця/латиниця, без ШІ (режим draft)
    tts_cache.py – синтез edge-tts із кешем на диску, спільний для всіх режимів
tests/ – тести чистих функцій (stdlib unittest, без залежностей)
presets/ – по файлу на тип ноти (схема полів/колоди/notetype), спільна для cards і audio
settings.toml.example – приклад налаштувань
draft.txt – сирий список для режиму draft
cards.txt – вхідний файл із картками (режим cards)
cards.txt.example – приклад cards.txt
audio_cache/ – локальний кеш згенерованих mp3 (режими cards і resync)
out/ – готові mp3 (режим audio) і сторінки на друк, pdf (режим pdf)
.cache/ – кеш TTS-фрагментів і тимчасові файли ffmpeg (режим audio)
```
