# anki-tts-filler

Заповнення карток у вже створеній **колоді/notetype** в **Anki** через [AnkiConnect](https://github.com/amikey/anki-connect). Скрипт не визначає вигляд картки чи структуру колоди – тільки дані (**текст + аудіо**). Схема полів і карток задається у файлах (`presets/*.toml`, `cards.txt`), не в коді – не привʼязаний до конкретної мови чи колоди.

## Як це працює

1. **Колоду** й **поля** створити та редагувати вручну в **Anki** (*поля, шаблон картки, CSS*).
2. Для кожного типу карток створити свій **пресет** – файл `presets/<назва>.toml` з тими самими назвами **полів** і **колоди**.
3. Записати список карток у `cards.txt` у форматі `ключ: значення`.
4. **Anki** має бути відкритий з увімкненим аддоном **AnkiConnect**.
5. Запустити скрипт із назвою пресету – аудіо генерується через `edge-tts` + `ffmpeg`, і картки додаються напряму в **Anki** через **AnkiConnect**.

## Встановлення

```bash
uv sync --no-editable
```

- Утиліти:
    - `ffmpeg`
    - [AnkiConnect](https://ankiweb.net/shared/info/2055492159) в **Anki** (`2055492159`, `Tools → Add-ons → Browse & Install`)

## Використання

```bash
uv run anki-tts-filler verb
```

**Anki** має бути запущений. Вхідні картки беруться з `cards.txt` у поточній директорії, схема – з `presets/verb.toml`.

Без аргументу скрипт друкує список доступних пресетів:

```bash
uv run anki-tts-filler
```

## Пресети (presets/*.toml)

Каталог `presets/` лежить поруч із `cards.txt`, у поточній директорії. Один файл – один тип картки; назва файлу без `.toml` і є назвою пресету. Якщо каталог порожній або його нема – скрипт створить `presets/example.toml` при першому запуску і вийде. Готовий приклад – `preset.toml.example` та `cards.txt.example`.

```toml
deck_name = "MyDeck::MySubdeck"
model_name = "MyNoteType"

[audio_fields]
audio_field_one = "field_one"
```

- `deck_name` / `model_name` – мають **дослівно** збігатися з назвами вже створених в **Anki** (для підтек – з `::`, як у самому **Anki**).
- `[audio_fields]` – `назва_аудіо_поля = "з_якого_текстового_поля_генерувати_аудіо"`. Ці аудіополя теж мають існувати в полях **Anki**. Якщо секції нема – аудіо не генерується взагалі.

Список і порядок текстових полів пресет не задає – вони беруться напряму з нотетайпу в **Anki** (`modelFieldNames`), мінус поля з `[audio_fields]` (вони генеруються, а не вводяться руками). Додати новий тип картки – це покласти ще один `.toml` у `presets/`, нічого не коментуючи й не редагуючи в наявних файлах.

## Формат вхідного файлу

Кожна картка – блок пар `ключ: значення`, розділений порожнім рядком:

```
field_one: значення першого поля
field_two: значення другого поля
```

Поле можна не писати взагалі або лишити значення порожнім – в обох випадках у **Anki** воно піде порожнім, без помилки. А от ключ, якого нема серед полів нотетайпу (одруківка в назві поля) – помилка, картка не додається; перевіряється в скрипті, не через **Anki**.

На кожну картку створюється одна нотатка напряму в **Anki**. Перед додаванням увесь список перевіряється через `canAddNotesWithErrorDetail`: дублікати й нотатки, які **Anki** відхилив би (наприклад, картка вийшла зовсім порожньою), рахуються окремо, скрипт **не падає**. Повтори всередині самого `cards.txt` теж ловляться – за першим полем нотетайпу, як це робить і сам **Anki**.

## Аудіо

Аудіо кешується в `audio_cache/` за хешем `текст + голос + темп`, тому зміна `TTS_VOICE`/`TTS_RATE` у `config.py` дає нові файли, а не перевикористання старих. У медіатеку **Anki** заливаються тільки ті файли, яких там ще нема.

## Структура проєкту

```
src/anki_tts_filler/
    main.py – точка входу (entry point anki-tts-filler), CLI і порядок кроків
    config.py – константи (TTS, AnkiConnect URL) і завантаження пресетів
    ankiconnect.py – HTTP-клієнт для AnkiConnect (localhost:8765)
    parser.py – парсинг cards.txt, побудова словника полів
    audio.py – генерація TTS-аудіо через edge-tts + ffmpeg
presets/ – по файлу на тип картки (схема полів/колоди/notetype, дані, не код)
preset.toml.example – приклад пресету
cards.txt – вхідний файл із картками
cards.txt.example – приклад cards.txt
audio_cache/ – локальний кеш згенерованих mp3
```
